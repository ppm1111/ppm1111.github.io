記憶化搜索 ＝ 暴力遞迴 ＋ 一本備忘錄

先用最小的例子：費氏數列 fib(n) = fib(n-1) + fib(n-2)。按播放，看暴力遞迴怎麼一遍又一遍重算同一個子問題，再切到「記憶化」，看整棵子樹被剪掉。

在呼叫棧中（計算中）已算完備忘錄命中，直接回傳這一步
重點：暴力遞迴的呼叫次數約是 1.6ⁿ（指數），但不同的子問題只有 n+1 個。把每個子問題的答案記下來，第二次遇到就直接查——這就是記憶化搜索，也就是「自頂向下」的動態規劃。

什麼題目可以用 DP？

問法

求「最大／最小」、「能不能」、「有幾種方法」，而且每做一個選擇，剩下的問題和原題長得一樣、只是更小。

重疊子問題

同一個小問題會被不同路徑反覆問到（像 fib(3) 被算了很多次）。這是加備忘錄有用的原因。

最優子結構 / 無後效性

大問題的答案只取決於小問題的「答案」，而不取決於你是怎麼走到那個小問題的。

每一題都套這四步

  1. 定義狀態：用一句中文說清楚 dfs(i, j) 代表什麼，例如「前 i 個數能不能湊出 j」。說不清楚，後面一定寫錯。
  2. 寫轉移：想「最後一步」做了什麼選擇（選或不選、用哪枚硬幣、最後戳哪顆氣球），每種選擇都變成一個更小的狀態。
  3. 定邊界：最小的狀態直接回傳答案，例如 i == 0、金額為 0。
  4. 加備忘錄：在 Python 加上 @cache（from functools import cache），就是記憶化搜索。之後把遞迴「翻過來」由小到大填表，就是遞推。

自頂向下 vs 自底向上

記憶化搜索（自頂向下）遞推填表（自底向上）
怎麼寫遞迴函式 + 快取，幾乎就是把轉移式直接翻成程式迴圈填 dp 陣列，要自己想好填表順序
計算順序需要誰就去算誰，系統自動處理順序必須保證算 dp[i][j] 時，它依賴的格子都已填好
算多少狀態只算「真的用得到」的狀態（後面動畫會看到很多格子是空的）整張表全部填滿
代價遞迴深度可能很深；函式呼叫有額外開銷常數小，容易做空間壓縮（二維變一維）
建議面試時先寫這個，正確率最高想優化空間或遞迴太深時再改

416. 分割等和子集

給一個正整數陣列，能不能把它分成兩組，讓兩組的總和相等？

轉換

兩組相等 ⇔ 能挑出一些數，總和剛好是 sum / 2。每個數只能「選或不選」→ 0/1 背包。

狀態

dfs(i, j)：只用前 i 個數，能不能剛好湊出 j。

轉移

看第 i 個數 x：不選 → dfs(i-1, j)；選（需 j ≥ x）→ dfs(i-1, j-x)。兩者有一個成立就成立。

邊界與複雜度

dfs(0, j) 只有 j = 0 為真。時間 O(n·t)，空間 O(n·t)，可壓到 O(t)。

目前格依賴的子問題在呼叫棧中已存入備忘錄命中

易錯點

  • 總和是奇數直接回傳 False，不用算。
  • 壓成一維 dp[j] 時，j 必須由大到小倒著跑：否則 dp[j-x] 已經是「這一輪」更新過的值，同一個數會被選兩次（那就變成完全背包了）。
  • 切到「記憶化搜索」看看：有不少格子從頭到尾都是空的——因為 or 短路，有些狀態根本不需要算。
Medium完全背包

322. 零錢兌換

給幾種硬幣面額（每種無限多枚）和一個金額，求湊出金額最少需要幾枚硬幣；湊不出來回傳 -1。這題最適合看清楚記憶化搜索的「呼叫棧」與「備忘錄」如何互動。

狀態

dfs(x)：湊出金額 x 最少要幾枚。

轉移

最後一枚用的是哪種硬幣 c？dfs(x) = min(dfs(x - c) + 1)，對每個 c 取最小。

邊界

dfs(0) = 0；x < 0 表示此路不通，回傳 ∞。

複雜度

狀態 amount+1 個，每個試 k 種硬幣：時間 O(amount·k)，空間 O(amount)。

目前格依賴的子問題在呼叫棧中已存入備忘錄命中
觀察：記憶化模式下，第一次會一路「鑽到底」dfs(11) → dfs(10) → … → dfs(0)，呼叫棧疊得很高；之後回溯時，幾乎每次呼叫都是紫色的備忘錄命中，一步就回來。

易錯點

  • 不能用貪心（每次拿最大面額）：例如 coins = 1,3,4、amount = 6，貪心得 4+1+1 = 3 枚，正解是 3+3 = 2 枚。可以把這組輸入貼上去試試。
  • 初始值要用 ∞ 而不是 0 或 -1，最後再把 ∞ 轉成 -1。
  • 完全背包的一維遞推，內層金額要由小到大正著跑——和 416 剛好相反，因為同一種硬幣可以重複使用。
Medium雙序列 DP

1143. 最長公共子序列

給兩個字串，求它們最長的公共子序列長度。子序列不必連續，但要保持原本的先後順序。例如 "ace" 是 "abcde" 的子序列。

狀態

dfs(i, j)：s 的前 i 個字元和 t 的前 j 個字元，LCS 長度是多少。

轉移

看最後一個字元：相同 → dfs(i-1, j-1) + 1（對角線）；不同 → max(dfs(i-1, j), dfs(i, j-1))（上、左）。

邊界

任一字串為空，LCS 為 0：i == 0 or j == 0。

複雜度

時間與空間 O(n·m)，空間可壓到 O(m)。

目前格依賴的子問題在呼叫棧中已存入備忘錄命中回溯路徑
動畫最後的紅框：表格填完後，從右下角往回走——字元相同就走對角線並記下該字元，否則往值比較大的方向走，就能還原出一個實際的 LCS 字串。

易錯點

  • dp 多開一行一列代表「空字串」，所以比較字元時是 s[i-1]、t[j-1]，下標很容易差一。
  • 和「最長公共子字串」不同：子字串要求連續，字元不同時要歸 0，而不是取 max。
  • 同一個模板可以直接用在 72 編輯距離：只是轉移變成三個方向取 min。
Hard區間 DP

312. 戳氣球

一排氣球各有數字。戳破第 i 顆得到 左鄰 × 自己 × 右鄰 分（超出邊界當作 1），戳破後左右兩顆變成相鄰。求戳完全部氣球的最大總分。

難點

如果枚舉「先戳哪顆」，戳完後左右會黏在一起，兩邊的子問題互相影響，無法拆開。

逆向思考

改成枚舉區間內「最後戳破」的氣球 k。k 活到最後，它就像一道牆把左右隔開，兩邊變成獨立子問題，而且戳 k 時它的鄰居一定是區間兩端 i、j。

狀態與轉移

兩端補 1 得 v。dfs(i, j)：戳完開區間 (i, j) 內所有氣球的最大分。max over k: dfs(i,k) + v[i]·v[k]·v[j] + dfs(k,j)

邊界與複雜度

i + 1 ≥ j 時區間內沒氣球，得 0。狀態 O(n²)，每個枚舉 O(n) 個 k：時間 O(n³)。

k：最後戳破左半 (i, k)右半 (k, j)區間端點 i、j表格中依賴的格子

易錯點

  • 遞推時一定要按區間長度由短到長填表（不是按 i、j 的順序），因為 dp[i][j] 依賴的 dp[i][k]、dp[k][j] 都是更短的區間。記憶化搜索則不用煩惱順序。
  • 開區間的定義讓 v[i]、v[j] 在 (i, j) 內的氣球全戳完之前都還在，乘積才會正確。
  • 相同套路的題：1039、1547 切棍子的最小成本。
